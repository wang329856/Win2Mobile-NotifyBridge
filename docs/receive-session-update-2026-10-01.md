# 接收会话、删除去重与短期队列

用户明确项目以新通知为主，不需要长期历史；选择一次手动接收会话：开始时清空旧列表，首次连接跳过旧通知；断网重连或切换 LAN/远程时保留本次消息并补收短暂断网期间的新通知。用户另要求删除的手机通知不能再出现，电脑不长期储存内容。

## 已实现行为

- 手机“开始本次接收”清空旧列表，开启新接收会话；停止后重新开始也开启新会话。自动网络重连、地址更新和切换接收方式延续原会话。
- LAN 首次连接使用 `live=true` 和经过证书验证的 hello 起点，只收之后通知。批准回复冻结 startSequence，LAN 与 ntfy 使用同一授权边界，不向新设备提供授权前记录。
- ntfy 新会话首次订阅不索取缓存；同一会话重连恢复消息 ID，认证后的会话前事件不保存。时间判断要求电脑与手机保持系统时钟准确。
- 手机详情增加单条删除，保存 eventId 删除标记；清空列表保留最大已接收序号。补发、重放和换传输不能重新插入已删消息。删除后仍推进必要的接收进度。
- Windows 只保留按入库时间最多 24 小时、最多 1000 条的短期发送队列，定时和入库时清理连续前缀；没有授权手机时不入库。超限/过期消息不补发。SQLite 全清理也不重置最高序号；LAN checkpoint 跳过已清理前缀，ntfy 丢弃已清理的待发分片并继续新通知。配对、证书、token 和设置继续持久保留。
