# 双设备验收

这份记录用于 Windows 与目标 Android 手机的实际运行验收。回环接口测试、JVM 测试和构建结果不能代替以下结果；在未执行前状态为「未验证」。

2026-10-01 用户反馈「现在测试已经通过」，并授权清理旧版及上传 GitHub。用户未提供逐项结果；下表保留可核对的安装和启动证据，其他场景的详细记录仍待补充。

## 首次使用

1. 使用目标机器信任的签名安装 Windows MSIX，从开始菜单启动。检查标题、托盘和「通知访问」状态。
2. 点击授权，在系统提示中允许。拒绝后检查应用能明确提示，再通过 Windows 设置恢复权限。
3. 手机安装 APK，开启通知权限并扫码。电脑批准前手机应显示等待，批准后应显示连接状态。
4. 点击电脑「发送测试通知」。手机应出现通知且历史记录可打开正文；电脑不能把仅入库称为手机已送达。
5. 触发一条其他 Windows 应用的系统 Toast。对比标题、正文、来源与时间；启动前通知中心里已有的内容应作为采集基线。

## 中断与恢复

1. 断开手机 Wi-Fi，电脑产生至少 20 条新 Toast。恢复 Wi-Fi 后，历史补齐且事件无重复，历史重放不成批响铃。
2. 关闭电脑代理后重启。手机恢复连接，已保存记录与游标继续使用，配对无须重新批准。
3. 手机息屏 30 分钟与一整晚，分别测试新通知。记录手机型号、Android 版本、系统电池设置、延迟与漏收条数；查看后台诊断，不以持续状态栏图标证明网络始终可用。
4. 重启手机，检查系统允许的前台接收是否恢复。手动「强行停止」后需要重新打开应用；系统行为不可等同于普通进程回收。
5. 电脑撤销手机，现有连接应关闭，旧凭据不能重新连接。手机重新扫码后必须再次由电脑批准。

## 日常管理

- 电脑暂停采集、产生 Toast、恢复：暂停期间内容不补发。
- 关闭一个来源的过滤开关：该来源之后的 Toast 不入库或发送，其他来源仍正常。
- 手机搜索、来源筛选、查看详情、删除历史及删除电脑：界面和持久状态一致。
- 电脑关闭窗口后继续接收；托盘退出后停止。登录启动默认关闭，启用、任务管理器禁用及再次登录分别检查。
- 更换电脑 IP / 多网卡：选择手机可达的地址，重新扫码更新连接信息，不能静默接受另一台电脑的证书。
