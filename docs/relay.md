# 跨网推送与自建中转

[返回项目介绍](../README.md) · [安装教程](installation.md) · [隐私说明](../PRIVACY.md)

局域网直连不依赖公共服务器。跨网是可选功能，电脑开关默认关闭；启用后默认使用第三方 **`https://ntfy.sh`**，也可填写兼容的自建 ntfy 根地址。使用公共服务无需自己租服务器，但需要两端能访问服务，并受服务可用性、限额和缓存策略影响。

## 选择连接方式

| 模式 | 适用情况 | 前提 |
| --- | --- | --- |
| 仅局域网 | 手机与电脑在可互通的局域网 | 有效 LAN 授权、可信证书与可达地址；无需互联网 |
| 仅跨网络 | 手机使用移动数据或外部 Wi-Fi | 电脑持续运行且开启跨网；手机持有对应中转凭据；两端可访问中转 |
| 自动（默认） | 希望在家用 LAN、离开后自动用中转 | 同时具有相应授权；仅 LAN 配对而未取得中转密钥时无法自动跨网 |

自动模式有 Wi-Fi / 以太网时，最多用 3 秒检查已保存的可信 LAN 地址，不可达则使用已有中转授权。中转稳定至少 30 秒且两次 LAN 检查成功后自动切回；可在手机电脑卡片详情指定模式。

## 开启默认跨网

1. 安装包含跨网功能的两端版本（当前正式版为 3.1.2），先按 [安装教程](installation.md) 完成权限设置。
2. 电脑打开「设置」→「跨网络推送」，启用加密跨网；展开「服务地址与代理」，默认服务为 `https://ntfy.sh`。
3. 若电脑需要已有 HTTP 代理，填写如 `http://127.0.0.1:7890` 的地址并保存；该设置只影响本应用的电脑中转连接，不配置手机代理。地址不能包含账号、路径或参数；留空使用系统网络。
4. 为手机取得中转授权：
   - **同一局域网**：启用中转后重新扫码配对，在电脑批准，以领取独立通知密钥。
   - **不在同一网络**：按下一节完成远程首次配对。
5. 手机切换到移动数据，确认该电脑允许跨网或自动模式，电脑点击「发送测试通知」验证接收。

不需要安装 ntfy App，也无需给 Windows 电脑开放公网入站端口。电脑中转代理可用不代表手机网络也能访问同一服务，两端须分别确认可达性。

## 完全远程配对

1. 电脑打开「连接手机」，选择「跨网络连接」，点击「启用跨网络并生成二维码」。
2. 通过可信渠道将二维码或复制的配对信息交给自己的手机，在 **120 秒**内扫码或粘贴。不要把二维码发到公开 Issue 或公开群组。
3. 核对两端显示的**六位校验码**，在电脑请求卡片批准。任意桌面页面都会显示待批准提醒。
4. 发送测试通知，确认手机收到；后续若回到 LAN，也可使用该授权对应的可信电脑地址。

远程配对通过临时 ECDH 协议加密授权回复，仍需电脑明确批准。过期时刷新二维码重试；未获批准不会领取长期设备凭据。

## 服务可用性与限额

`ntfy.sh` 是独立运营的第三方公共服务，本项目不控制它的 SLA、网络连通性、缓存时长或免费额度。**具体限额以 [官方发布文档](https://docs.ntfy.sh/publish/#limitations) 的现行规则为准**，不将当前免费额度作为永久承诺。自建服务的限额由其配置决定。

- **分片占额度**：通知加密后按分片发布，多部手机分别发送；每手机、每分片和重试均消耗请求额度，不等于一条 Windows 通知只占一次请求。
- **限流会延迟**：中转返回 HTTP 429 时电脑按 Retry-After 等待；没有该值时默认等待 15 分钟。其他网络或服务错误会重试，电脑短期队列最多保留 24 小时 / 1000 条。
- **缓存会过期**：手机离线过久时可能产生缺口。回到 LAN 后可补收本次会话中仍在电脑队列里的消息；超过队列上限或属于旧会话的内容不保证恢复。
- **中转接收不是送达确认**：「中转已连接」仅说明手机与中转连接成功，不表示电脑在线、历史完整或手机已保存全部通知。
- **后台仍受系统限制**：手机 Doze、厂商电池策略和网络切换会影响 WSS 接收；前台服务也不保证息屏时必达。

出现延迟时先查看两端连接诊断与限流状态，不必立即清除手机数据或重复配对。授权被撤销或证书 / 身份异常时，应核验后再恢复该电脑接收。

## 自建 ntfy 服务

项目已有自定义中转入口：电脑「设置」→「跨网络推送」→「服务地址与代理」→「中转服务地址」。例如填写 **`https://ntfy.example.com`**；这是格式示例，需要换成你实际部署的服务。

### 兼容条件

| 项目 | 当前要求 |
| --- | --- |
| 服务类型 | 兼容 ntfy 发布及订阅 API |
| 地址 | HTTPS 服务器根地址，可含端口；不能含子路径、账号、查询参数或片段 |
| TLS | 手机标准 CA 与主机名验证须通过；不复用 LAN 的自签名证书绑定机制 |
| 发布 | 允许对随机 `w2m_` topic 执行匿名 POST，支持本项目的加密分片 |
| 订阅 | 支持 WSS、实时接收与按消息 ID / since 参数读取缓存 |
| 反向代理 | 保留 WebSocket 升级与连接，转发 ntfy 所需请求和响应头 |
| 客户端鉴权 | 当前没有 ntfy 账号、密码、Bearer token 或付费 topic ACL 配置入口 |

不能将一个要求 ntfy 登录 / token 的服务直接填入客户端期待其自动完成认证。随机 topic 和消息加密不等于服务器访问控制；匿名入口仍可能被其他人消耗资源。自建时应根据自己的网络环境规划访问范围、限流、缓存与运维，不把禁用全站鉴权作为通用部署建议。

### 部署与接入步骤

1. 按 [ntfy 官方安装文档](https://docs.ntfy.sh/install/) 部署服务；按 [官方配置文档](https://docs.ntfy.sh/config/) 设置 HTTPS、WebSocket、缓存和限流。具体服务器命令以选用版本的官方文档为准。
2. 在电脑和手机网络分别检查服务可达、证书有效，以及符合上表的发布 / 订阅能力。能够打开网页不等于 WSS 与匿名 topic 已可用。
3. 在 Win2Mobile 电脑端填写自己的 HTTPS 根地址，保存并启用跨网，然后为手机配对并发测试通知。
4. 保持电脑运行，分别验证移动数据接收、断网重连和息屏恢复；监控自己的日志、缓存与额度。

**更换已有设备绑定的中转地址时，需要先在电脑撤销绑定旧服务的设备，再保存新地址并重新配对。** 现有 topic、密钥和接收游标不会自动迁移到新服务器。更换前先记录所需配置，避免影响仍在使用的手机。

手机更新 LAN 地址只修改本地直连地址，不会修改独立保存的中转地址；LAN 地址变化可编辑或扫码更新，仍需匹配原电脑身份和证书。

## 加密与停用边界

通知内容在电脑加密、手机解密，每部手机有独立 topic 与 AES-256-GCM 密钥。中转服务看不到通知明文，但可见 IP、topic、事件 ID、大小与时间等元数据；它仍是可用性和密文缓存的依赖。

手机「仅局域网」、关闭接收或暂停，不会停止电脑中转发布。需要停止发布时，请关闭电脑跨网开关；只停用某部手机时，在电脑设备页撤销它。撤销不能追回已经进入中转缓存的密文或手机已接收的内容。

协议与测试边界见 [ntfy 协议 v1](protocol-ntfy-v1.md)，实机检查见 [跨网验收清单](ntfy-device-validation.md)，数据保留与删除见 [隐私说明](../PRIVACY.md)。
