# 跨网使用与自建中转

[返回项目介绍](../README.md) · [首次安装](installation.md) · [隐私说明](../PRIVACY.md)

手机和电脑在同一局域网时，不需要开启中转。离开局域网后想继续接收，电脑必须保持运行并启用跨网；默认使用第三方 **`https://ntfy.sh`**，两端都需要能访问它。

## 开启跨网推送

1. 电脑打开「设置」→「跨网络推送」，启用加密跨网。服务地址保留默认 `https://ntfy.sh`。
2. 手机取得中转授权：
   - 两端在同一局域网：启用中转后重新扫码，在电脑批准，以领取独立中转密钥。
   - 两端不在同一网络：按下一节远程配对。
3. 手机电脑卡片保持「自动」模式；直连不可用时会尝试使用已授权中转，也可选择「仅跨网络」。
4. 手机切换移动数据，电脑点击「发送测试通知」，确认收到。

不需要安装 ntfy App，也不需要给 Windows 电脑开放公网入站端口。

若电脑连接中转需要已有 HTTP 代理，可展开「服务地址与代理」，填写如 `http://127.0.0.1:7890` 的地址并保存；留空使用系统网络。代理只影响本应用的电脑中转连接，不会设置手机网络；地址不能包含账号、路径或参数。

## 不在同一网络时配对

1. 电脑打开「连接手机」→「跨网络连接」，点击「启用跨网络并生成二维码」。
2. 通过可信渠道把二维码或复制的配对信息交给自己的手机，在 **120 秒**内扫码或粘贴。
3. 核对两端显示的**六位校验码**，在电脑批准请求。
4. 电脑发送测试通知，确认手机收到。

二维码属于临时授权材料，不要公开分享。过期时在电脑刷新，未获批准的手机不能接收。

## 选择连接模式

| 模式 | 适用情况 |
| --- | --- |
| 自动（推荐） | 在局域网优先直连，无法直连时使用已授权中转 |
| 仅局域网 | 只在可互通的局域网接收 |
| 仅跨网络 | 只通过已配置中转接收 |

自动回退需要手机已取得中转密钥。只完成局域网配对、没有启用并授权中转时，离开局域网后无法接收。

## 服务可用性与限额

`ntfy.sh` 是第三方公共服务，本项目无法保证它持续可用。网络不可达、服务故障、限流或缓存过期可能造成延迟与消息缺口。当前规则见 [ntfy 官方说明](https://docs.ntfy.sh/publish/#limitations)。

- 长通知会加密分片，每个分片、每部手机和重试都会消耗额度。
- 遇到限流时电脑等待后重试，但队列最多保留 24 小时 / 1000 条。
- 手机离线过久、中转缓存过期时，可回到 LAN 补收本次会话中仍在电脑队列里的内容。
- Android 息屏和厂商后台限制仍可能影响接收；前台服务不保证始终联网。
- 「中转已连接」只说明手机连上中转，不代表电脑在线或全部消息已送达。

先查看两端状态与网络，遇到延迟不必立即清除数据或反复配对。

## 自建 ntfy 服务

在电脑「设置」→「跨网络推送」→「服务地址与代理」中，把中转地址换成自己的 HTTPS 根地址，例如 `https://ntfy.example.com`（需要换成实际部署的地址）。

当前客户端要求：

- 兼容 ntfy 的匿名 topic 发布和订阅 API，支持 WSS 与缓存恢复。
- HTTPS 根地址，可含端口；不能含子路径、账号、查询参数或片段。
- 服务证书通过手机标准 CA 与主机名验证，反向代理支持 WebSocket。
- 不要求客户端提供 ntfy 账号或访问 token；本项目目前没有这些配置入口。

部署方法见 [ntfy 官方安装](https://docs.ntfy.sh/install/) 与 [配置文档](https://docs.ntfy.sh/config/)。自建者负责访问范围、限流、缓存和维护；随机 topic 与加密不等于服务器访问控制。

更换已绑定的中转服务时，先在电脑撤销绑定旧服务的手机，再保存新地址并重新配对。电脑和手机需分别验证能访问新服务。

## 停止跨网与隐私

手机暂停接收或选择「仅局域网」不会停止电脑发布。需要停止全部中转时，关闭电脑跨网开关；只停用某部手机时，在电脑设备页撤销它。

通知内容在电脑加密、手机解密，每部手机使用独立密钥。中转仍可见 IP、topic、事件 ID、大小和时间，已缓存密文无法追回。数据保存与删除的完整说明见 [隐私说明](../PRIVACY.md)。
